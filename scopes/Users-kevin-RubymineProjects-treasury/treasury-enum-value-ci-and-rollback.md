Adding a value to a persisted `T::Enum` in treasury (e.g. `Transfers::Metadata::PaymentProcessor`, `Transfer::State`) has two traps neither `bundle exec rspec` nor `srb tc` catches.

**1. Regenerate two sets of artifacts or CI hard-fails.**
- `make graphql` — GraphQL enums are *derived* from the Ruby enums (`app/graphql/types/transfers/metadata/payment_processor_enum.rb` does `PaymentProcessor.values.map(&:serialize).each { value _1 }`). Updates `schema.graphql`, `schema.json`, `frontend/lib/types/graphql.ts`, `graphql-fragments.ts`. `bin/ci/ensure_server_in_sync` + `ensure_next_client_in_sync` byte-compare them.
- `make rbi` — `sorbet/rbi/dsl/transfer.rbi` enumerates one predicate per state (`queued?`, `can_transition_to_queued?`), generated by the TSM tapioca compiler. `bin/ci/ensure_sorbet_in_sync` runs `tapioca dsl --verify`. Note `sorbet/rbi/dsl/transfers/metadata.rbi` does NOT need regenerating — it types getters as the enum class, value-agnostic.

**2. It's a one-way deploy unless you split the PR.** Both deserializers **raise** on an unknown persisted string: `typed_state_machine_v2.rb:50-52` (`values.find { ... } || raise ArgumentError`) and `typed_enum_attribute.rb:77-79`, the latter also installing a validation on the *raw column* so any later `save` on the row fails. Blast radius is not the one row: `balance_computation.rb` iterates `outgoing_transfers.pending` calling `transfer.queued?` → breaks balance computation for the whole CustomerAccount; `payments/health/transfers/evaluation_service.rb` scopes `.pending` then switches on `current_state` → kills the entire 15-min `Payments::Health::MonitorJob` run org-wide. `Transfer.pending` is a DB-level `where.not(state: terminal)`, so old code still loads the poisoned row.

Fix = expand/contract: **PR 1 ships the enum value + every reader; PR 2 flips the writer.** Reverting PR 2 then leaves readers that still parse everything persisted. **Only works if PR 1 actually deploys first** — same deploy for both and an image rollback takes both, so the split buys nothing. Say that when proposing it.

Shipped this way for BANK-1595 (PRs #8417 readers / #8418 writer). See [[treasury-mmf-sell-completion-validation]].
