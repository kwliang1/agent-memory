The `balance_check_records.in_progress_*` columns + "In-Progress Adj." UI column (shipped 2026-07-08 in #8121, which folded #8122+#8137) have NO writer on main — every record has defaults, UI shows "—".

**Why the writer was killed (deliberate, BANK-1556):** v1 (PR #8097 closed; #8101 is a stale open leftover) computed adjustments in a standalone `In(Progress|Flight)AdjustmentService` whose `Result` carried per-transfer details; `DifferenceService#run!` persisted them. Kevin's v2 decision: "v2 puts the corrections where they belong: inside BalanceService" → `CustomerAccounts::BalanceService.external_payment_processor_balance` (Flipper `external_payment_processor_balance`). v2 returns a bare `Money`; the per-transfer detail is computed inside private adjustment methods and discarded — no metadata surface survived.

**Collateral:** BANK-1557's acceptance criteria ("DifferenceService#run! populates them", "always populated, even with flag off") never shipped, but the issue was marked Done 2026-07-08 when the stack merged. The columns/UI are scaffolding awaiting a v2-native writer.

**Intent to populate is unambiguous (Kevin confirmed 2026-07-08):** the shipped stack includes `BalanceCheck::SlaLevel` (with `allows_adjustment?`), `EvaluationService.evaluate_transfer_sla`/`evaluate_book_transfer_sla`, a per-transfer loop in `transfer_v2_destination_credit_adjustment` (balance_service.rb:205-212) that computes (transfer, sla_level, adjusted?) and discards it, and a fully-built frontend tooltip consumer (`InProgressTooltipContent`). Only the last mile is missing: collect details in the adjustment loops → persist in `DifferenceService#run!` (BANK-1557: always populate, even flag-off, for pre-rollout audit).
