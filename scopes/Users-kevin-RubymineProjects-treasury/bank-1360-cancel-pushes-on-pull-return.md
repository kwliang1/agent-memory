**THE CRUX — no push↔pull relation exists anywhere (verified exhaustively, 2 Explore agents + direct):**
- Venture does NOT cancel downstream pushes on pull return — only reverses the inbound *contribution* (`venture treasury/event_consumer_service.rb:345`, `sync_service.rb` cancels `Investment::Payment`/`SubscriptionSegment` via `treasury_ach_pull_id`). Treasury owns the cascade cleanly.
- Legacy `AchPush`/`AchPull`: zero association, no FK, no shared `transfer_metadata_id`; `waiting_for_funds_from` is NEVER set to a pull (only CrossTransfer/BookTransfer/QueuedTransfer, via `fdic/mirror_account/transfer_service.rb:88` + `transfers/create_service.rb:294`).
- Modern `OutgoingPayment`/`FundingPlan`: its funding steps (`FundingPlanStep` purposes IvcPull/MirrorPull/CrossTpLeg) are INTERNAL CustomerAccount→CustomerAccount `Transfer`s (`ivc_cascade.rb` builds cca→iva→on_core), NEVER an external AchPull. So OP doesn't capture the external-pull→push tie either.
- OP↔ACH push support = live but flag-gated migration: DIBS ACH on; Treasury Prime ACH behind `:outgoing_payment_treasury_prime_submit` + per-plan-type Flipper; Fifth Third ACH excluded; else legacy AchPush + shadow OP (`ach_pushes_handler.rb:65-112`, `outgoing_payment/info_service.rb:145 processor_supports_op?`).
- Kevin initially insisted "there should already be a relation" → after evidence, conceded "I was incorrect, build 1."

**Build decision (approach 1 = create the tight relation):**
- Linkage = nullable `ach_pushes.funded_by_ach_pull_id` FK (NOT `waiting_for_funds_from` — the real producer, an insufficient-balance queued push, is a bare `AchPush.queued`, not a QueuedTransfer, so nothing to hang polymorphic waiting_for_funds on without re-plumbing).
- Producer = `AchPushes::StateService.provision!`: when queueing for insufficient cash balance, set funded_by_ach_pull ONLY if exactly one covering pending inbound pull into same account (else null). Safe-biased: only cancels not-yet-sent pushes → wrong guess delays a disbursement, never sends money we don't have.
- Cascade = new `AchPulls::ReturnCascadeService.cancel_dependent_pushes!` wired into `mark_pending_return!` + `return!` (idempotent). Pre-submission states cancel INLINE (no network — no TP/DIBS id yet); `submitted`-TP via after-commit job (TP cancel = network call, hard-no in txn). STATSD + structured log per cancel.
- Race guard in provision!/submit!: refuse if funded pull pending_return/returned.
- Reuse: `AchPushes::StateService.cancel!` already cascades to destination QTs via `cancel_queued_transfers_into_account!` (only hits network post-submission). 

**Entry points for pull return:** SVB/file path = `incoming_ach_file.rb:149` → `mark_incoming_return!` → `mark_pending_return!`, then `bai2_sync_files/ach_processing_service.rb:296` → `return!` (separate). TP/DIBS = `SubmittableAchs::StateService.return_pull!` = both in one txn.
