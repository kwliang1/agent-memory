Running treasury specs from a throwaway `git worktree` (not the main checkout) needs several env fixups, because worktrees don't get the repo's git-ignored local files and the dockerized services are only reachable on host-published ports:

- **Ruby:** the session may export `ASDF_RUBY_VERSION=3.4.5` while the repo needs 3.4.8 (`.tool-versions`). `unset ASDF_RUBY_VERSION` so asdf falls back to `.tool-versions`. NOTE: a *running* Claude session caches the env at launch — fixing the shell profile only helps NEW sessions; this one stays stale until restart. The pre-commit/husky hooks inherit the stale session env too.
- **Env vars:** worktrees lack `.env`/`.env.local`. The full set of required vars (encryption keys `TREASURY_ENCRYPTION_*`, `AL_API_CLIENT_ID`, etc.) lives in `.devcontainer/.env`. Export the well-formed lines: `while IFS= read -r l; do export "$l"; done < <(grep -E '^[A-Za-z_][A-Za-z0-9_]*=' /Users/kevin/RubymineProjects/treasury/.devcontainer/.env)` (plain `source` chokes on that file's non-KEY=VAL lines).
- **DB/service hostnames → host ports** (override the docker hostnames the devcontainer env sets): MySQL `treasury-mysql-1` → `TREASURY_DATABASE_HOST=127.0.0.1 TREASURY_DATABASE_PORT=3307`; Postgres `treasury-postgres-1` → `TREASURY_DATABASE_PG_HOST=127.0.0.1 TREASURY_DATABASE_PG_PORT=5437`; MinIO `treasury-minio-1` → `MINIO_ENDPOINT=http://127.0.0.1:9000`. (Port 3306 is `angellist_mysql`, NOT treasury.)
- **husky in worktrees:** `.husky/_/` is git-ignored (created by install) so it's absent in worktrees; `core.hooksPath=.husky` then makes pre-commit/pre-push fail with `.husky/_/husky.sh: No such file`. Copy it from main: `cp -R <main>/.husky/_ .husky/_`. The pre-push hook only guards pushing `main` — it `exit 0`s otherwise.
- **Unrelated pending migrations:** `spec/rails_helper.rb` `maintain_test_schema!` aborts on any pending migration. For mock-only unit specs (no DB), temporarily soften that rescue in the worktree (throwaway), then `git checkout -- spec/rails_helper.rb`.
- Pre-push review gate: `unset MOCK_ENTITY_API` so local mocks don't hide failures (the gate itself is defined in the global CLAUDE.md).
- **App secrets beyond `.devcontainer/.env`:** some code fetches secrets at class-load (e.g. `Crypto::Commitments::Layer2Service` does `ENV.fetch('LAYER2_OAUTH_URL')` on load, hit via `IncomingWires::CreateService` → `AutoAssignService`). `.devcontainer/.env` lacks the `LAYER2_*` set → `KeyError` when the create/auto-assign path runs. Pull just those from the running container: `while IFS= read -r l; do export "$l"; done < <(docker exec treasury env | grep -E '^LAYER2_')`. **Do NOT bulk-import `docker exec treasury env`** — it carries `GEM_HOME=/usr/local/bundle`, `BUNDLE_APP_CONFIG=/usr/local/bundle`, `RUBY_VERSION`, `RAILS_ENV=development` which clobber host asdf ruby/bundler (bundler then can't materialize the gemset, falls back to system ruby 2.6). Cherry-pick only the app-secret vars you actually need. Working recipe saved at scratchpad `spec_env.sh` pattern.

**Committing from a worktree (2026-08):**
- The husky `pre-commit` hook runs `bun run lint-staged`, which is NOT installed in the worktree → `git commit` fails with `Script not found "lint-staged"`. Workaround: run the lint-staged equivalent manually — `bundle exec rubocop --auto-correct --fail-level error --force-exclusion <changed .rb files>` (that's exactly what `lint-staged` runs for `*.{rb,rake}` per package.json) — then commit with `git commit --no-verify -S`. `--no-verify` skips the broken husky hook; `-S` still signs (branch protection needs verified signatures). NOTE `%G?` shows `N` locally (no `gpg.ssh.allowedSignersFile` configured) — verify the signature landed with `git cat-file commit HEAD | grep "SSH SIGNATURE"`, not `%G?`.
- A PreToolUse `.claude/hooks/pre-commit-claude-docs-check.sh` blocks the FIRST `git commit`/`gt modify` and creates a 5-min marker (`/tmp/.claude-docs-audited-<branch>`); audit the Claude docs (grep CLAUDE.md + `.claude/skills/*/SKILL.md` for your changed symbols), then re-run the same commit — it passes while the marker is fresh. It compares `main...HEAD`, so on a branch stacked on another feature branch the file list includes the whole stack, not just your diff.
- **TRAP (cost me repeated lost-fix cycles):** NEVER put `git add -A` in the SAME Bash command as `git commit`. The docs hook is PreToolUse — it inspects `.tool_input.command`, sees `git commit`, and blocks the ENTIRE compound before anything runs, so the `git add` is silently skipped. The subsequent `git commit --amend` retry then commits STALE staging (your fix is left uncommitted in the working tree — `rspec` still passes because it reads the working tree, but the pushed commit / CI is missing the fix). ALWAYS: (1) `git add -A` in its own command (no `git commit` in it) so it actually runs, (2) verify with `git diff --cached --stat`, (3) `git commit --amend` in a separate command, (4) after committing verify `git status` is clean AND `git show HEAD:<file>` has your change before pushing.
