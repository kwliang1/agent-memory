**Bug:** `BalanceCheck::Record#pending_activity_match_kind` partitioned classify-only incoming credit rows into confirmed(mandatory)/in-transit(subsettable) by `record_type` (`IN_TRANSIT=['Transfer']`). But the incoming-revision collector (#8268, `balance_service.rb` `transfer_v2_pending_incoming_adjustment`) emits bank-CONFIRMED money as `'Transfer'`, `credit`, `adjustment_cents:0` → wrongly subsettable → subset search could EXCLUDE confirmed money to reconcile a gap = false `expected_to_settle` masking a real discrepancy.

**Fix:** explicit `const :bank_confirmed, T::Boolean, default:false` on `InProgressDetail`, set at the collector; `collect_detail!` gained a `bank_confirmed:` kwarg. Three classify-only credit collectors pass `true` (incoming revisions, `collect_confirmed_unledgered_wires!`, `collect_unbridged_dibs_credits!`); genuine in-transit `collect_pending_incoming_transfers_v2!` stays default false. `pending_activity_match_kind` partitions via new private `bank_confirmed_credit_row?(row)`: flag if boolean, else LEGACY_CONFIRMED/IN_TRANSIT_CREDIT_RECORD_TYPES record_type decode (renamed from CONFIRMED_/IN_TRANSIT_), else nil→fail closed. Additive `json` column key — NO migration; legacy rows recompute identically.
