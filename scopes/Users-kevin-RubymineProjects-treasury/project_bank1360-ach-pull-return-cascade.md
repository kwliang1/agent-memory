Final commit `a0e3ebd7e` (signed, **NOT pushed** — PR #8778 still holds the older sync commit `c382a6884`; push = force-push to replace it).
- `AchPulls::StateService#mark_pending_return!` posts the ADJUSTMENT clawback LE (customer→pull, gated `if ach_pull.completed?`) and, inside the same txn, enqueues `Temporal::Activities::AchPulls::CancelDependentPushesActivity` via `BackgroundOutboxActivityDispatcher.call` (transactional outbox → runs post-commit).
- The activity resolves the pull's `customer_account`, and under `MysqlAdvisoryLock.with_lock("cancel_dependent_pushes:#{ca.id}", timeout: 30)` cancels HELD pushes (AchPush with needs_review `PENDING_ACH_PULL_SETTLEMENT` hold, on that CA, `order(:created_at)` oldest-first) via `AchPushes::StateService.cancel!`, **breaking as soon as `customer_account.cash_balance` is no longer negative** (fresh unmemoized read each iter → cures the deficit without over-cancelling). Per-push rescue → ErrorTracker + `status:errored`; single metric `treasury.ach_pull.dependent_push_cancel` tagged `status:`(cancelled/skipped/errored)+`processor:`.
- Guard: `ReviewReason#can_approve_by_reason?` for an AchPush holder → `return false if account.customer_account.cash_balance.negative?` (was pull-state `FAILED_STATES` based — that const DELETED). OW/OP keep prior `elsif ach_pull.returned? || ach_pull.cancelled? → true`.

**Why this dissolved the old problems:** balance-driven + balance-aware means we stop caring WHICH pull is named on the hold → the multi-pull `.last` gap AND the NEEDS_ADMIN_ATTENTION wedge both vanish, no N-holds needed. Load-bearing invariant (re-verified 4× by adversary): a pending PENDING_ACH_PULL_SETTLEMENT hold ⟹ push in `in_compliance_review` ⟹ pre-submission ⟹ no TP/DIBS id ⟹ `cancel!` makes NO bank call, is a local ledger reversal. Advisory lock serializes concurrent same-account cancel activities (fixes bounded over-cancel); lock name grep-unique → one-directional order vs `LE_*` ledger locks → no deadlock; `LockTimeout`→Temporal retry (idempotent).
