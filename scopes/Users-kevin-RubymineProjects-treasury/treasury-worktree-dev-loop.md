Isolated treasury worktree dev loop (verified 2026-07-10, worktree `.worktrees/treasury-tide`):

- Create off latest main: `git fetch origin main && git worktree add -b <branch> /Users/kevin/RubymineProjects/.worktrees/treasury-<name> origin/main`
- One-time DB: `make setup-worktree` (creates DBs, loads schema, migrates). Then `make up` (starts the worktree's own app container `treasury-<name>`; shares main's mysql/postgres/minio).
- Run tools against the worktree's container with BOTH compose files:
  `docker compose -f docker-compose.yml -f docker-compose.worktree.yml exec -T app bundle exec rspec <path>` (also `srb tc`, `rubocop <files>`).
- **Go through `make`, not raw `docker compose`** (verified 2026-07-27). The Makefile derives `TREASURY_WORKTREE_NAME` from `basename $(CURDIR) | sed 's/^treasury-//'` and exports it; that env var is what names the container `treasury-<name>`. A bare `docker compose -f … up -d app` without it defaults the name to **`treasury-worktree`** — a shared name every worktree would collide on. Use `FILES="<paths>" make spec` / `make up`, or export `TREASURY_WORKTREE_NAME=<name>` explicitly. (`make spec` = `$(COMPOSE) exec -e RAILS_ENV=test app bundle exec rspec $(FILES)`.)
- **When `make up` won't stay up, don't fight it — use a one-off container.** On a fresh worktree (2026-07-28, `treasury-moss`) `make up` died instantly: the overmind-managed `frontend` process exited 127 on a bun/`next` tarball-extract error and took the whole container down with it (`docker logs` shows `signal: interrupt` for app/prophet/temporal/solid_queue). `exec` then fails with `service "app" is not running`. Specs/sorbet need no web server, so run them detached from overmind:
  `cd <worktree> && TREASURY_WORKTREE_NAME=<name> docker compose -f docker-compose.yml -f docker-compose.worktree.yml run --rm --no-deps -T app bash -lc 'bundle exec srb tc; env -u MOCK_ENTITY_API bundle exec rspec <paths>'`
  `run --rm` auto-names the container so there's no collision, and `--no-deps` skips the shared mysql/postgres/minio it doesn't need. Also: `.worktree-port` caches a port that may already be taken by a sibling worktree — `rm .worktree-port` forces a re-scan. Do NOT use `run` WITHOUT `--no-deps` — it boots the worktree's own mysql/postgres/minio and collides on the shared 3307/etc. ports (`Bind for 0.0.0.0:3307 failed: port is already allocated`); clean the orphans with `docker rm -f <name>-mysql-1 <name>-postgres-1 <name>-minio-1`.
- **`setup-worktree`/specs failing with `git@github.com:angellist/ipseity (at main@<sha>) is not yet checked out. Run 'bundle install' first` = stale gem bundle** (2026-07-29). The `app-gems` named volume (`/usr/local/bundle`, per docker-compose.yml) lags the worktree's Gemfile.lock git-gem ref; `make rebuild` does NOT fix it. Fix once (persists to the volume): `docker compose -f docker-compose.yml -f docker-compose.worktree.yml run --entrypoint "" --rm --no-deps app bundle install`, then `make setup-worktree` + specs work.
- Rubocop-on-changed-lines only: run rubocop on the diff's files, expand `git diff -U0` hunk headers into `file:line` pairs, and `grep -Ff` the offense list against them — treasury files carry dozens of pre-existing offenses that are not yours.
- Commit signing: SSH signing via 1Password works but `git commit`/`--amend` can land UNSIGNED silently; re-sign with `git rebase --gpg-sign -f HEAD~1`. Verify with `git cat-file commit HEAD | grep -c gpgsig` (`%G?` shows N locally only because no allowedSignersFile — GitHub still verifies). Push with `--no-verify` (husky broken in worktrees). See [[shared-checkout-worktree-isolation]].
- **rubocop is NOT a blocking CI gate** in treasury's Buildkite pipeline (`.buildkite/pipeline.rb` runs rspec, sorbet, config/sync checks only) — but still fix `Style/ReturnNil` etc. on touched lines; a pre-push review agent will flag them.
- **Venture (`angellist`) prod console is FORBIDDEN** for Kevin's role: `al console -a angellist -p` → `Forbidden: cannot get pods in namespace angellist-ro`. Treasury prod console works (see [[treasury-prod-console-access]]); to resolve a venture `User` → email, ask someone with venture access or use another source.
- **CI-watch: key on the `buildkite/treasury/pr` ROLLUP, not a shard subset.** rspec is knapsack-sharded (`rspec-treasury-0..3`); a watch loop that exits when "the shards I see" are non-pending can miss a still-running shard and report green falsely (burned once, 2026-07-11, PR 8203 — rspec-treasury-3 failed after I called it green). Wait for `buildkite/treasury/pr` to be pass/fail.
- **Before pushing a cross-cutting change (e.g. swapping a state machine), run the CONTRACT specs, not just the files you touched.** Migrating `Applications::MoneyMarketFund` to `TypedStateMachineV2` failed `spec/models/typed_state_machine_v2/display_protocol_spec.rb`, which asserts every TSMv2 model also `include TypedStateMachineV2::Display`. TSMv2 models must include BOTH `TypedStateMachineV2` and `::Display`; define a `State < T::Enum` with a `terminal?` method; states inferred from `transition(name:, from:, to:)` (no `method:`/initiator needed for simple transitions); `transition_to!(State::X)` for changes; `.state` still returns the serialized string; predicates (`active?` etc.) auto-generate from serialize values; run `tapioca dsl <Model>` + commit the RBI.
- **Fix the dead `make up` instead of working around it** (2026-10-05, glyph): the `next: command not found` crash is a broken `<wt>_frontend-node-modules` volume. Repair once: `TREASURY_WORKTREE_NAME=<name> TREASURY_APP_PORT=<port> docker compose -f docker-compose.yml -f docker-compose.worktree.yml run --entrypoint "" --rm --no-deps -T app bash -lc "cd frontend && rm -rf node_modules/* && bun install"`, then `make setup-worktree` + `make up` work. Specs then run via `docker exec -e RAILS_ENV=test treasury-<name> env -u MOCK_IPSEITY -u MOCK_ANGELLIST bundle exec rspec …`. If the container later dies with `OOMKilled=true` (`docker inspect`), it's Docker-VM memory pressure from sibling stacks, not the app — just `make up` again. Browser auth still needs the `/etc/hosts` alias from [[worktree-ssr-auth-gap]]; seed data via `docker exec … rails runner` (`db:seed` needs `NONINTERACTIVE=1` and fails on the existing admin). Playwright with `channel: 'chrome'` avoids a browser download.
