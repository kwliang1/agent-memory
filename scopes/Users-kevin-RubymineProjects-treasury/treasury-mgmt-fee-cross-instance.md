Diagnosed INC-5385 (Netz Select mgmt-fee release fails "check the account has enough balance" despite ~$1.39M).

**Treasury Prime has two INSTANCES** (`treasury_prime_instances`, separate TP setups/keys): `main` (program *Grasshopper Bank Main* = "GHB main") and `management_company` (program *Grasshopper Bank Management Company*, id 4). A **management-fee payout is a cross-INSTANCE transfer** `main → management_company` — see `treasury/app/services/transfers/create_service.rb` `cross_instance_special_case?` (`from.main_instance? && from.ghb? && to.management_company_instance?`) → `create_cross_instance_transfer!` ("special logic ... to assist with management fee payments").

**Failure mode:** if the recipient mgmt-co CA has `active_sub_account == nil` (no `management_company`-instance sub-account provisioned), `to.management_company_instance?` is false → cross-instance path never fires → transfer can't build → raises. cptr `payments/state_service.rb:270` wraps ANY treasury error in a hardcoded misleading string `"Unable to complete transfer on treasury. Check that the account has enough balance."` — the balance text is boilerplate, ignore it; the cause is in `e.message`.

**Target state** for a mgmt-fee recipient: `account_purpose == MANAGEMENT_COMPANY` (164 such CAs, all have an active sub-account on program *Grasshopper Bank Management Company* / instance `management_company`). Fix for an unprovisioned one = provision that sub-account (+ set purpose MANAGEMENT_COMPANY); ops/provisioning, no code deploy.

**Routing knob (cptr side):** `CPTR::FundExpense.recipient_treasury_account_id` is a **uuid** = the treasury CA's uuid. `payment_to_management_company?` keys off `recipient_treasury_account.account_purpose == :MANAGEMENT_COMPANY`. Do NOT repoint mgmt fees to a CARRY_RECIPIENT account — its sub-account is on `main`, not `management_company`, and it commingles carry with fees.

**Access gotcha:** the cptr routing row lives in the cptr DB, and my k8s RBAC is **Forbidden** in `comptroller`, `venture`, AND `angellist` namespaces (write & read) — only `treasury -p -w` is reachable from this session. Couldn't independently confirm `recipient_treasury_account_id`; had to trust Sky's RCA on that one link. Related: [[treasury-prod-console-access]].
