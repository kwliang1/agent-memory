Investigated 2026-07-09 (reef session), treasury repo. Question: "why can't we return an IncomingWire when it's returned in TreasuryPrime." Tickets BANK-1596 (Wise), BANK-1598, BANK-1606 — all same family as [[unprocessed-ach-return-overcredit]].

**Manual path WORKS.** `Mutations::IncomingWires::Return` (return.rb:22) → `IncomingWires::StateService.return!`. State machine allows `return` from Created/Provisioned/Transferred/Hold/PendingReturn (incoming_wire.rb:197-202). `return!` from Provisioned posts one reversing entry `IncomingWire → External Outgoing Funds` cat=RETURN (state_service.rb:245-259). Admin "Return Wire" button = this. Gap is purely automation.

**Automatic paths — only TWO, both description-string matchers on `account.update` txn scans:**
1. `[WIRE RETURN] WIRE IN` desc → AchSyncService (ach_sync_service.rb:147, matcher :438) → `IncomingWireSyncService.return_incoming_wire!(txn[:incoming_wire_id])` (incoming_wire_sync_service.rb:260). Requires TP to post that exact desc AND an `incoming_wire_id` field = original `treasury_prime_wire_id` (spec ach_sync_service_spec.rb:472-508). Built for Piermont (commit d6d7d8874).
2. `DEPOSIT RETURN ITEM` on GHB checks account, matched by amount → WebhookTransactionSyncService (webhook_transaction_sync_service.rb:51-54).

**Root causes:**
- TP pushes NO incoming-return event. Subscribed webhooks (webhook_config_service.rb:153-162): account.update, ach.update, incoming_wire.**create** (never .update), wire.update, transaction.create, book.update, apply.*. TP's valid-event list (:20-86) has no `incoming_wire.update` / `incoming_ach.*`. `ach.update` only routes to things WE originated — AchPull/AchPush/CrossTransfer/Transfer/OP (webhook_service.rb:131-152); an incoming ACH credit falls through → RAISES "ACH not found".
- **Returned incoming ACH credits = dead end (BANK-1596/1598).** Wise = INCOMING ACH CREDIT modeled as IncomingWire payment_type=Ach. Return reversing txn desc is NOT `[WIRE RETURN] WIRE IN`; the incoming-ACH filter only selects INCOMING ACH CREDIT/DEPOSIT prefixes (ach_sync_service.rb:50) + `next if amount <= 0` (:152) drops the negative. Nothing fires return!. `AchPull/AchPush#mark_incoming_return!` (NACHA return files, incoming_ach_file.rb:149) only covers ACHs we pull/push, never incoming credits.
- **Wire path brittle (BANK-1606, iw_…):** if returned wire lacks the `[WIRE RETURN] WIRE IN` desc or the `incoming_wire_id` linkage, `return_incoming_wire!` gets nil → silent early-return (incoming_wire_sync_service.rb:262).

**Recommended systemic fix:** add an incoming-ACH-return detection branch parallel to the wire path (match the ACH reversing txn in AchSyncService → route to return_incoming_wire!, or subscribe to an incoming_ach.update webhook if TP exposes one). Verify on prod console what TP actually posts (desc + incoming_wire_id presence) before building, so the fix matches the real payload.

**Design verified 2026-07-09 (reef), TP docs + prod reads:**
- TP DOES offer `incoming_ach.create`, `incoming_ach.update`, `incoming_wire.create`, `incoming_wire.update` (docs.treasuryprime.com/reference/webhook-events). We subscribe ONLY to incoming_wire.create. Prod WebhookEvent counts: incoming_wire.create=133,978; incoming_wire.update / incoming_ach.update / incoming_ach.create = 0 → TP sends nothing unsubscribed. Both VALID_EVENTS list AND configure_default_webhooks! omit the .update events.
- TP incoming_ach object: `status ∈ {pending, done, failed, returned}`; field **`original_transaction_id`** = the `ttx_` account-transaction id (+ `related_transaction_ids`). PATCH incoming_ach/{id} with status=`return` + return_code (R10/R20/R29) is how ops returns one.
- **Join key confirmed:** ACH-credit IncomingWires store `treasury_prime_wire_id = ttx_…` (the txn id, ach_sync_service.rb:163), which == incoming_ach.`original_transaction_id`. The 3 returned wires (295427/312923/306566) are all payment_type=ach, direction=credit, GHB Main, tp_wire_id=ttx_… (e.g. 295427=ttx_11mtbjs88wp1ee5 vs ticket inach_11mtbjs58wp1d3d, same id-cluster). Incoming *wire* IncomingWires instead store iw_… (link directly via incoming_wire.update event_id).
- Exposure at design time: 93 provisioned IncomingWires w/ sub_account (42 ACH-credit ≈ $3,005, mostly microdeposits; rest = older wire tail).
