Kevin finds verbose explanations tedious to read (said so 2026-07-10). Be concise EVERYWHERE: Slack replies, PR descriptions, and inline code comments. Lead with the answer/decision, cut preamble and recap, tight bullets over paragraphs, drop belabored rationale unless asked. PR bodies: short — what + why + testing, no essays. Inline comments: one terse line, WHY only. Keep memory files trimmed, don't append endlessly.

**Why:** he reads fast on Slack and wants signal, not a wall.
**How to apply:** default to a few lines. Expand only when he asks for depth or it's a genuinely load-bearing design/safety point. One tight table beats prose.
