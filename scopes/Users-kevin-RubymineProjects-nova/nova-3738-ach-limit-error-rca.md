**NOVA-3738** (Nova Papercut Patrol): red form error `ACH limit exceeded: $250,000` shows on the Amount field for **internal Nova senders** transferring >$250k, even though wire is valid/required above the cap. Reported by Kevin 2026-08-07.

**RCA (verified):** `BalanceInput.tsx` amount `onChange` set `form.setError('transferAmount', …)` via `shouldShowAchLimitError`, which returns true only for `sender-internal` — exactly the senders who *can* wire. It was independent of the selected method (shows before wire is picked) and only cleared on a later under-limit amount change (persists after picking wire). Early `return` also skipped the `getNewTransferType` auto-switch-to-WIRE. The genuinely-blocking case (external-linked / ACH-pull-only, `sender-external-linked`) is separately enforced in `form.ts` zod `.refine` (lines ~107-121) — unaffected.

**Introduced:** PR **#6201** (commit `c1b7c868`, Edwin Zhang, 2026-12-29) — inverted the condition `sender-ach` (external, can't wire → error correct) → `sender-internal` (can wire → error wrong). PR **#6343** (Pradyuman Vig, 2026-01-07) then removed external ACH/wire accounts from the modal, orphaning the error onto the wrong population. Went unnoticed b/c: young modal (~Dec 2025), narrow trigger (internal + >$250k), non-blocking (form.ts doesn't enforce it for internal), and the only tests on the path **blessed the bug** — unit `transferRules.test.ts` "returns true for internal sender when amount exceeds ACH limit"; unmerged e2e test 8 (branch `kevinliang/nova-278`) expects the "$250,000" error. No transfer-modal e2e is merged to main.
