**INC-5376 (2026-07-27):** 12 nova distribution transfers stuck across 2 orgs (some since Feb 2026), incl. 3 Capital Factory Fellowship-fund transfers ($7,800 wire, $7,500 ACH, $525 wire). Treasury rejects with `External wire account not authorized for this entity`. Transfers strand silently CLEARED-but-unsubmitted (`completeTransfer` is fire-once, no reconciler — Andrew Mahon wants one built).

**Mechanism:** for a **deduplicated `ipseity_entity`** external account, `OutgoingWiresHandler#create` requires `EWA.entity_id == input.entity_id` (`treasury/app/handlers/outgoing_wires_handler.rb:38`). Nova submits the **sender fund's** ipseity id as `input.entity_id` (`nova/graph/src/services/distribution/payments/initiate/index.ts:548`), but a recipient payout account is owned by the **recipient** → can never match → 403. Fix = flip recipient EWA/EAA to a nova-space type so the entity-equality check is dropped.

**entity_id_type enum** (`treasury/app/types/external_accounts/entity_id_type.rb`): `ipseity_entity` (CA-ownership enforced), `nova_entity`, `nova_directory_entity` (latter two = `nova_managed?`, no CA, entity-level). Nova branch in handlers gates ONLY on `customer_account.source == CustomerAccount::NOVA` — ignores entity_id entirely. Verified incident sender CA `b4649bf2…` has `source:"nova"` ✅. Prod counts (2026-07-27): nova_entity=1 EWA (Kevin's precedent flip, 2026-06-29), nova_directory_entity=228 EWA/10 EAA, ipseity=89k EWA/114k EAA.

**🚨 BLOCKING for ACH:** `treasury/app/models/outgoing_payment.rb` `validate_destination_entity_consistency` — WIRE branch (`:611-614`) has the `nova_managed?` short-circuit; **ACH branch (`:625-628`) does NOT**. Flipping an EAA → `destination.entity_id`(nova UUID) ≠ `origin.owner_entity_api_id`(ipseity) → `RecordInvalid` (shadow-OP spam always + hard fail when op_enabled). Must mirror the wire branch before flipping any EAA. Handler-layer auth (`ach_pushes_handler.rb:25-42`, `ach_pulls_handler.rb`) already has the nova branch — only the OP validation is missing it.

**Reads (Kevin's question — will sender-org reads break? Answer: no):** all sender self-view surfaces fetch via `batchGet…Accounts({ids})` (treasury index-by-ids has NO entity filter → immune). No nova code consumes the `entity_id` *value* (wire schema doesn't even carry it). Breaks only on flipped records via `find_by!(uuid,entity_id,entity_id_type)` on show/list-by-entity: (1) transfer-counterparty display `nova/graph/src/internal/loaders/externalAccounts.ts:80/105` (show-fallback passes ipseity → RecordNotFound → **degrades to null**, only rejected/archived/unvalidated recipient accts w/o cached name); (2) provision dedup-match `provision/wire.ts:70` → duplicate-account risk on re-provision; (3) entity-sync best-effort silent; (4) `financialAccounts.ts:249` dead code. CAVEAT: sender query `externalAchAccount/get.ts:37` relies on ipseity default but is scoped to FIRST_PARTY → keep flip scope to **recipient payout accounts only**.

**Other treasury gotchas:** `find_ewa!/find_eaa!` (`external_wire_accounts_handler.rb:217`/`external_ach_accounts_handler.rb:166`) break for stale-ipseity show/archive/update callers; `copy_from_existing` hardcodes ipseity (`api/external_wire_accounts_controller.rb:136-139`); dedup `invariance_uniqueness` groups by entity_id → **flip all siblings of an underlying account together**.
