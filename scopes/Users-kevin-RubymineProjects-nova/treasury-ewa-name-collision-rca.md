Incident (2026-08-07, Backend Capital secondary buyout thread): wire from Gryphon 17, LLC to LP **Fan Zhang** (acct `<acct-3 redacted>`, GHB routing `<routing-1 redacted>`) went out with beneficiary **"1 HOUR LUNCH BREAK LLC"** (Richard Antablian). **WRONG first theory (do not repeat):** I blamed treasury's EWA dedup key `(entity_id, account#, routing)` excluding `beneficiary_name` + a shared GHB FBO omnibus account number. **Kevin refuted both:** "That's wrong" and "Ghb omnibus has nothing to do with it." The bug is UPSTREAM in **nova** ("Nova wire weirdness," per Thomas).

**Correct area — nova's off-platform payee directory (repo `nova`, `packages/prisma/models/`):**
- `DirectoryEntity` (`directory.prisma`) — GP's off-platform payee record, owned by `senderOrganizationId`, free-text `name` ("1 HOUR LUNCH BREAK LLC").
- `EntityExternalBankReference` (EEBR) (`banking.prisma`) — links EITHER on-platform Nova `entityId` OR off-platform `directoryEntityId` to treasury account pointers (`externalWireAccountId`/`externalAchAccountId`); EEBR stores no name.
- Directory-owned EEBR's treasury account is created under `entity_id = directoryEntity.id`, `entity_id_type = 'nova_directory_entity'` (`data/entity/entityExternalBankReference.ts:92-93`, `externalWireAccount/clone.ts`) — a DISTINCT treasury account from the LP's real ipseity-owned one.

**How the name is created & why it diverges from treasury's EAA:**
- GP seeds via `createDirectoryEntityWireReference` → `upsertForDirectoryEntity`; the GP-typed `beneficiaryName` is written straight into a new treasury EWA/EAA `beneficiary_name`/`account_holder_name` under the directory entity (`upsertForDirectoryEntity.ts:211,245`). Also seeded by cloning ("GP record seeded from an LP," `clone.ts`). Captured ONCE at seed time; read back as `legalName` (`listForRecipient.ts:202,225`).
- Nova matches directory records to entered bank details by **account# + routing ONLY, never name** (`matchDirectoryEntitiesByBankDetails.ts` `wireMatches`/`achMatches`; `getCounterparty`; `externalWireAccount/otbLines.ts findMatchingEwa`). So a directory row seeded with Richard's name against acct `<acct-3 redacted>` surfaces/returns for anyone entering that acct#, and provisioning reuses it (`provision/wire.ts:39` `beneficiaryName: eebr.bankDetails.legalName`) → wire gets the stale directory name. LP's real EAA is never consulted for the name.
