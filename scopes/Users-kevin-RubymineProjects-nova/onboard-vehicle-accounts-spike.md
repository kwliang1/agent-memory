Spike (started 2026-07-20) to enhance `nova/graph/engbot/onboardVehicleAccounts.ts` to fold the manual treasury-console → ipseity-console → JSON → nova-console onboarding dance into one engbot run. Four asks: (1) fund identity-data upsert, (2) signatory/control-person related entities, (3) KYC trigger, (4) BONUS partner-bank-program. Reference ruby script: `~/Library/Application Support/JetBrains/RubyMine2025.3/scratches/nova/onboarding/impatient_ventures/impatient_ventures_n_spv_llc.rb` (uses legacy `EntityAPI::*` + treasury console models, NOT Prophet).

**Verdict: ipseity side fully buildable on EXISTING nova Prophet endpoints — zero ipseity backend work. Only real gap = treasury partner-bank migration, and only if accounts must be FBO.**

Nova→ipseity/treasury is Prophet (NATS RPC) ONLY — no treasury GraphQL client in nova (`graph/src/clients/treasury/request.ts` SERVICE='treasury').

Reference-script call → nova client method → ipseity Prophet handler:
- `EntityAPI::Entity.new + init_identity_data + FirmData.fill` → `clients.ipseity.updateEntityRaw` (`entities:update`) with `company_identity_data` (name, tax_id=EIN, incorporation_type/country/state/date, current_address, meta_entity_type='fund', exemption_*) + `disclosures` (n_beneficial_owners→beneficial_owners_count, subject_to_foia, is_ngo_or_charity, is_professional_service_provider, is_securities_commodities_firm, is_fund_of_funds, 3c1/3c7). ALL FirmData.fill fields are Prophet-reachable (schemas: entity_prophet_api `messages/identity_data/company.rb`, `messages/disclosures.rb`; persisted same models as `KycFillService`).
- `Roles::Signatory/ControlPerson.new.save!` → `clients.ipseity.createRole` (`roles:create`) `{entityId, relatedEntityId, roleType:'signatory'|'control_person', metadata:{title}}`. Links EXISTING related entity id (does not create the person).
- `Verification.confirm_roles/verify_identity/verify_related_entities` → `clients.ipseity.finalizeEntity` (`entities:finalize` `{id, async?}`) — folds all three. NO standalone Prophet verify actions; `should_alloy_verify`, `verify_watchlist`, and `force`/granular verify have no Prophet surface (not needed for this flow).

Two constraints from the ruby reference that are MOOT/relaxed on the Prophet path:
- "Link signatory BEFORE FirmData.fill else phantom Person" — phantom is only created by legacy `KycFillService.find_or_create_signatory_role!`; Prophet `entities:*` never auto-creates a signatory. Just need roles linked before finalize.
- KYB `disclosures` booleans NOT required for finalize to pass (traced FinalizeService→KybService.confirm_roles! + verify services: zero reads of those fields). `confirm_roles!` needs only: ≥1 control_person linked + each owner's OWN identity data complete (person: name+dob+ssn/passport+address). Send disclosures anyway for compliance completeness. If `exemption_category` set → confirm_roles skipped entirely.

- `MigrationService.migrate!` is GraphQL-only (`Mutations::PartnerBank::Program::Migrate`) — NO Prophet route. Grep treasury `config/prophet.rb` for migrat/program = nothing.
