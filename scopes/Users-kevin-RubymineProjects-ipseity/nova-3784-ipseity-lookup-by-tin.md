**Contract (as built):** IN `{tins:[{ref,tin,entity_type?}]}` cap ≤500 → OUT `{results:[{ref,status:found|no_match|kms_error,candidates:[{entity_id,entity_type,name}]}]}`. Bounded, partial-success per row, map results to inputs by `ref`.

**Design decisions (grounded in code):**
- Files: new `app/services/entities/tax_id_info_service.rb` (class **`Entities::IdentityLookupService` (method `lookup_by_tax_ids(queries)`, no bang — pure read; file `app/services/entities/identity_lookup_service.rb`)** — renamed from TaxIdLookupService per Kevin, matches `*InfoService` read-service convention) + `entity_prophet_api/.../messages/entities/lookup_by_tax_id.rb` (predeclare module + require in `entity_prophet_api.rb`) + `EntitiesHandler#lookup_by_tax_id` (`parse_lookup_input` guard) + route in `config/prophet.rb` + `/\Atin\z/` in `config/initializers/filter_parameter_logging.rb`.
- Cap lives IN the service: `MAX_QUERIES = 500` + `TooManyQueriesError` (raised in `.call`, handler rescues → `Prophet::InvalidRequestError`). Statuses in a frozen `STATUSES = [found,no_match,kms_error]` (spec asserts every result ∈ set). `TAX_ID_TYPES = [Entity::COMPANY, Entity::TRUST, Entity::IRA]` (reuse Entity constants, not literals). Domain routing symbols `:ssn`/`:tax_id` are internal; authoritative hash domain = `config.domain` from each model's BlindIndexConfig.
- **Reuses each model's OWN `BlindIndexConfig`** via `IdentityData::Person.blind_index_mappings.fetch(:ssn_bidx)` / Company's `:tax_id_bidx` — so read normalization stays locked to the write path. Person=ssn(strip_non_digits), Company/Ira/Trust=tax_id(strip_separators), all identical (guard spec asserts it).
- **One indexed read per identity table** (`where(bidx: digests).includes(:entity).group_by(&col)`), no fan-out. Domain choice from `entity_type` hint; **ssn domain only for US-numeric TIN (no letters, 9 digits) on EVERY path incl. person hint** (else a foreign id strips to digits and matches an unrelated SSN). No-hint numeric → both domains (disregarded-entity SSN==EIN). Domains DON'T cross-match (HMAC prefixes `"domain:"`).
- **KMS soft-fail:** `compute_hmac` RAISES on outage (write-path degradation only) → `#prepare` scrubs invalid encoding up front + has a **method-level `rescue StandardError`** → per-row `kms_error`, reported via PII-safe `BlindIndexConcern.report_degraded(error_class:)`. Never 500s the batch.
- **PII:** raw TIN never returned/logged/in-exceptions. The `/\Atin\z/` filter was **load-bearing** — Prophet logs `request.args` on every call and `tin` wasn't in `filter_parameters` (only ssn/tax_id).
- **`kyc_verified` OMITTED** from the batch candidate (was in the original contract sketch): `Entities::VerificationService.verified?` is recursive + side-effectful (builds KYC-AML statuses, fans out to owners/control-persons) — unsafe ×500. KYC belongs at the confirm/port step per matched entity, via existing `entities:show`.
